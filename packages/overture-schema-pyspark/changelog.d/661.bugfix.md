Fixed the validation registry coming back empty when `overture-schema-pyspark` is loaded from a wheel on `sys.path` (zipimport) rather than installed to a real directory, as happens on AWS Glue via `--extra-py-files`. The registry now discovers generated modules through `overture.pyspark_validations` entry points read via `importlib.metadata`, which resolve whether the package lives on disk or inside a zip archive.
